# Real-Time Monitoring and Alerting of Quick-Commerce Delivery Service

## Overview

This project implements a real-time monitoring and alerting system for a simulated quick-commerce delivery service.

The application generates delivery-related metrics using Python and exposes them through a Prometheus metrics endpoint. Prometheus collects and stores these metrics, while Grafana provides a dashboard for real-time visualization. Alert rules are configured to detect operational issues such as high pending deliveries and increased delivery times. Jenkins is used to automate the application deployment pipeline.

Make sure the following are installed:

## 1. Install Python Dependency

Install the Prometheus Python client:

```bash
pip install prometheus-client
```

## 2. Run the Delivery Metrics Application

Run:

```bash
python delivery_metrics.py
```

The application starts an HTTP server on port `8000` and continuously simulates delivery data.

Example output:

```text
[INFO] Starting the HTTP server on port 8000...
[INFO] HTTP server started. Simulating deliveries...
[DEBUG] Total deliveries: 69
[DEBUG] Pending deliveries: 20
[DEBUG] On-the-way deliveries: 17
[DEBUG] Average delivery time: 28.26 seconds
```

The metrics are exposed at:

```text
http://localhost:8000/metrics
```

The main metrics generated by the application are:

| Metric                  | Description                               |
| ----------------------- | ----------------------------------------- |
| `total_deliveries`      | Total number of deliveries                |
| `pending_deliveries`    | Number of pending deliveries              |
| `on_the_way_deliveries` | Number of deliveries currently on the way |
| `average_delivery_time` | Delivery-time observations                |

## 3. Configure Prometheus

Prometheus is configured using `prometheus.yml`.

The configuration defines the application as a Prometheus scrape target and loads the alert rules.

Example:

```yaml
scrape_configs:
  - job_name: "prometheus"
    static_configs:
      - targets: ["localhost:9090"]

  - job_name: "delivery_service"
    static_configs:
      - targets: ["<delivery-service-host>:8000"]

rule_files:
  - /etc/prometheus/alert_rules.yml
```

> The delivery-service target should be changed according to the Docker/host networking configuration being used.

## 4. Run Prometheus

Prometheus can be run as a Docker container with the configuration files mounted into the container.

After starting Prometheus, open:

```text
http://localhost:9090
```

Navigate to:

**Status → Targets**

The `delivery_service` target should show:

```text
UP
```

This confirms that Prometheus is successfully scraping the application's metrics.

## 5. Configure Alert Rules

Alert rules are defined in:

```text
alert_rules.yml
```

### High Pending Deliveries

The first alert is triggered when pending deliveries remain above 10 for 15 seconds:

```yaml
- alert: HighPendingDeliveries
  expr: pending_deliveries > 10
  for: 15s
  labels:
    severity: warning
```

### High Average Delivery Time

The second alert monitors average delivery time:

```yaml
- alert: HighAverageDeliveryTime
  expr: (average_delivery_time_sum / average_delivery_time_count) > 30
  labels:
    severity: critical
```

These alerts help identify delivery-service performance problems.

Open Grafana:


## 7. Configure Prometheus as Grafana Data Source

In Grafana:

```text
Connections
    → Data Sources
    → Prometheus
```

Configure the Prometheus server URL according to the Docker networking setup.

Click:

**Save & Test**

A successful connection confirms that Grafana can retrieve metrics from Prometheus.

## 10. Testing Alerts

To test the pending-delivery alert, increase the simulated pending-delivery range in `delivery_metrics.py`.

For example:

```python
pending = random.randint(50, 100)
```

This produces values above the alert threshold of 10.

After restarting the application, the alert can be verified through Prometheus and Grafana.
